# Easy Restaurant: แนวทางแยก Import หลายร้าน

สถานะ: ข้อเสนอสำหรับระบบจริง ยังไม่ได้เชื่อมฐานข้อมูลหรือเปิดใช้งานการอ่านไฟล์อัตโนมัติ

## หลักการ

ชื่อ A103 / S102 / S104 / S114 / S117 ระบุชนิดรายงาน ไม่ใช่ร้าน ใช้ Report Template ชุดเดียวกันทั้ง 3 ร้าน และแยกข้อมูลด้วย `brand_id` และ `branch_id` ที่ระบบกำหนด

S107 ยกเลิกการใช้แล้ว (03/09/26): ไม่แสดง Template และปฏิเสธชื่อไฟล์ที่ระบุรหัส S107 ก่อนเพิ่มเข้าคิว Import การตรวจนี้เป็นระดับชื่อไฟล์; ระบบต้นแบบยังไม่ได้อ่านเนื้อหาไฟล์ที่ผู้ใช้เปลี่ยนชื่อ

## ขั้นตอนที่แนะนำ

1. Administrator เลือกร้าน + สาขา + ช่วง Business date ก่อนเลือกไฟล์ ไม่ใช้ร้านที่กำลังเปิดดู Dashboard เป็นปลายทางโดยอัตโนมัติ
2. สร้าง Import Batch ที่ล็อกปลายทาง เช่น Capricci / 00001 / 01/09/26 ไฟล์ในคิวไม่เปลี่ยนร้านเมื่อสลับ Dashboard
3. ใช้ชื่อไฟล์เสนอ `report_type` จากนั้นตรวจหัวรายงานหรือคอลัมน์จริงอีกครั้งก่อนเลือก parser
4. ตรวจตัวตนในเนื้อหากับทะเบียนร้าน: ชื่อร้าน/นิติบุคคล + เลขผู้เสียภาษีของผู้ประกอบการ + รหัสสาขา + Source Profile อย่าใช้เลขผู้เสียภาษีของลูกค้าในตาราง A103 มาระบุร้าน
5. ถ้าร้านหรือวันที่ไม่ตรง ให้หยุดในสถานะ NEEDS REVIEW ห้ามย้ายเข้าร้านอื่นหรือแทนที่ข้อมูลเอง ถ้าขาดข้อมูลระบุตัวตน ให้ Administrator ยืนยันพร้อมเหตุผล
6. แสดง Preview จำนวนแถว ยอดรวม ช่วงวันที่ และส่วนต่าง ก่อนกดยืนยันบันทึก
7. บันทึกแบบ atomic transaction พร้อมประวัติผู้นำเข้า เวลา แหล่งไฟล์ เวอร์ชัน parser และผลตรวจสอบ ยกเลิกทั้ง batch เมื่อ validation สำคัญไม่ผ่าน

## ป้องกันไฟล์ซ้ำและการนับยอดซ้ำ

- เก็บ SHA-256 ของไฟล์และ `brand_id + branch_id + report_type + period_start + period_end + source_profile_id`
- ถ้า hash เดิมในปลายทางเดิม: แจ้งไฟล์ซ้ำและไม่เพิ่มยอด
- ถ้า hash เดิมถูกกำหนดไปอีกร้าน: กักตรวจสอบ แทนการอนุญาตข้ามร้านทันที
- ถ้า period เดิมแต่ไฟล์เปลี่ยน: สร้าง revision รออนุมัติแทนรุ่นเดิม ไม่ append ยอดซ้ำ และเก็บรุ่นก่อนให้ตรวจย้อนหลัง
- ถ้ารายงานครอบคลุมหลายวันหรือช่วงวันที่ทับกัน ต้องตรวจ overlap ที่ระดับวัน/ธุรกรรม ไม่ใช่ดูชื่อไฟล์เท่านั้น
- S102/S104/S114/S117 เป็นมุมมองที่อาจซ้ำของยอดชุดเดียวกัน ห้ามนำยอดรวมของแต่ละรายงานมาบวกเป็นรายได้รวม
- ใช้ S104 เป็นตัวเลือกแหล่งรายการขายระดับบิลหลังยืนยัน business rules; S102/S114/S117 ใช้ตรวจยอดและสรุป และ A103 แยกเป็นทะเบียนภาษี ไม่เพิ่มยอดขายซ้ำ
- อย่า deduplicate สินค้าในบิลด้วยเลขบิล + รหัสสินค้าอย่างเดียว เพราะอาจมีหลายบรรทัดจริง ต้องมี line identity จากระบบต้นทาง หรือใช้ revision ของรายงานร่วมกับลำดับแถว
- ใช้ decimal หรือหน่วยย่อยที่แม่นยำในระบบจริง เก็บค่าดิบและค่าที่แสดงแยกกัน: CSV ชุดนี้มี 109622.422 แต่รายงาน PDF แสดง 109622.42

## ช่องทางการส่งไฟล์

เริ่มต้นด้วยการ Upload แบบเลือกปลายทางชัดเจน เมื่อมี backend แล้วค่อยเพิ่มกล่องรับแยกร้าน เช่น `Capricci/00001/2026-09-01/`, `KAPPO/<สาขาที่ลงทะเบียน>/...`, `LAWOI/<สาขาที่ลงทะเบียน>/...` แต่ละกล่องต้องผูกกับ Source Profile ฝั่งระบบ ชื่อโฟลเดอร์หรือ prefix เป็นเพียงตัวช่วย ไม่ใช่หลักฐานอนุญาตสิทธิ์

ชื่อไฟล์เดิมเก็บได้โดยไม่ต้องเปลี่ยน หากต้องการตั้งชื่อให้อ่านง่าย ใช้ `CAPRICCI_00001_S102_20260901.csv` เป็นทางเลือก แต่ยังต้องตรวจเนื้อหาและ metadata เหมือนเดิม

## ขอบเขตของหน้า UX/UI รุ่นนี้

มีตัวเลือกร้าน สาขา วันที่ และคิวไฟล์ Excel/CSV/PDF ที่ตรึงปลายทางไว้ ชื่อไฟล์เสนอ report type ได้ แต่ยังไม่อ่านเนื้อหา ไม่ตรวจ hash ของไฟล์ใหม่ ไม่ตรวจสิทธิ์ และไม่บันทึกเข้า server ไม่มีระบบ import production
