# Revenue Control Center - HTML และ Source code

## อัปเดต Master Data: KAPPO FoodStory

- ตัดกล่อง Reconciliation ออกจากหน้า Master Data ของ KAPPO TAKASHI
- ตาราง Data Management แสดง Unit Sold, Unit Price และ Total Amount ตาม Period ที่เลือก
- Unit Sold รวมจำนวนขายจากรายละเอียดบิล, Unit Price แสดงราคาขายที่พบในรายงาน และ Total Amount รวมราคาสุทธิสินค้าหลังส่วนลดสินค้า
- ช่วงที่ไม่มีรายงานแสดง NO DATA; เมื่อมีรายงานแต่เมนูนั้นไม่มียอดขายจะแสดง 0

## อัปเดต Dashboard: Layout และ Import File

- เรียงเนื้อหาใหม่เป็น Sale (Monthly) + Sales (Daily), กราฟ Total Sale, Weekday Ranking, Guest Check-In + Guest Daily และ Entertain
- ตัดสถานะ “Master Data ต้นแบบ · ยังไม่เชื่อมส่วนกลาง (หลัง Final)” ออกจาก Dashboard
- Import File เป็น Feature ชุดเดียวกัน จึงแสดงเฉพาะหน้า Master Data; ปุ่ม Import ด้านบนจะเปิดหน้า Master Data และเลื่อนไปยังส่วน Import ของร้านที่เลือก

## อัปเดต Dashboard: Weekday Ranking · Calendar Month

- เปลี่ยน Weekday Analysis เป็น Weekday Ranking และตัด Weekday Traffic Ranking · 4 Weeks ออก
- เพิ่มแท็บ Summary และ Week 1–Week 5/6 ตามจำนวนสัปดาห์จริงของเดือนที่เลือก โดยแบ่ง Monday–Sunday และตัดช่วงหัว/ท้ายให้ตรงกับเดือน
- Summary แสดง Week ที่มี Guests รวมมากที่สุดและวันที่มีลูกค้าเข้าใช้บริการมากที่สุด ส่วนแต่ละ Week แสดงวันที่ลูกค้ามาทานมากที่สุดพร้อมข้อมูลรายวัน
- ร้าน Easy Restaurant ใช้ Guests จาก S117; SUSHI SARYU และ Maison Dunand ใช้จำนวนลูกค้าจาก FoodStory Bill Summary
- วันที่หรือร้านที่ไม่มีรายงานแสดง NO DATA และไม่นับเป็น 0; รายงานที่ระบุ Guests = 0 ยังคงเป็นข้อมูล 0 จริง

## Refresh และ Period

- แก้ปุ่ม Refresh: ใช้กล่องยืนยันในหน้าเว็บแทนกล่องของเบราว์เซอร์ กด Go to Backup เพื่อสำรอง หรือ Cancel เพื่อกลับโดยไม่ล้างข้อมูล แล้วกด Reload Page เมื่อตรวจไฟล์สำรองแล้ว หากมีแบบร่าง Master ที่ยังไม่ใช้กับ Dashboard ต้องเก็บแบบร่างหรือทดลองใช้ก่อน Export Current Data
- หากคำสั่งโหลดใหม่ถูกปฏิเสธหรือหน้าเดิมยังอยู่หลัง 4 วินาที ปุ่มจะหยุดหมุนและแจ้งวิธีกู้คืน โดยไม่ล้างข้อมูลเองและไม่ลองโหลดซ้ำอัตโนมัติ คำเตือนข้อมูลยังไม่บันทึกยังทำงานเมื่อปิด/รีโหลดเอง
- แท็บที่เปิดค้างยังใช้โค้ดเดิม: สำรองข้อมูลในแท็บเก่าก่อน แล้วเปิด Revenue-Dashboard.html ในแท็บใหม่หรือใช้ Reload ของเบราว์เซอร์หนึ่งครั้งเพื่อรับรุ่นแก้ไข หลังจากนั้นเปิด Backup กลับมาได้

- ตัด Box Period แยกด้านล่างออกแล้ว เลือกวันและช่วงวันที่ทั้งหมดจาก Box วันที่ด้านบน แสดงวันที่เป็น DD/MM/YY และเปิดปฏิทินตรงตำแหน่งนั้น
- เปิด Box วันที่ด้านบนเพื่อแสดงปฏิทินสองเดือน ช่องวันเริ่มต้น–สิ้นสุด และช่วงลัดด้านขวาตาม Reference
- เลือกวันเดียว: คลิกวันหนึ่งครั้ง แล้วกด “เลือก”; เลือกช่วง: คลิกวันแรกและวันสุดท้าย หรือกรอกทั้งสองช่องเป็น DD/MM/YY แล้วกด “เลือก” คลิกย้อนลำดับได้ ระบบเรียงวันให้
- เลือกวันย้อนหลังหรืออนาคตได้โดยไม่ผูกกับวันนำเข้ารายงาน มีตัวเลือกเดือน/ปีสำหรับข้ามไปวันอื่นอย่างรวดเร็ว ข้อมูลไม่ครบหรือไม่มีเลยไม่ใช่เงื่อนไขปิดปุ่มใช้วันที่
- ช่วงลัด: วันนี้ / เมื่อวานนี้ / 7 วันล่าสุด / 30 วันล่าสุด / เดือนนี้ / เดือนที่แล้ว / ปรับแต่งเอง อ้างอิงวันที่ปัจจุบันตามเวลาไทย; 7/30 วันนับรวมวันนี้ ส่วนเดือนเลือกครบเดือนปฏิทิน กด “เลือก” เพื่อยืนยัน กด “ยกเลิก” หรือปิดปฏิทินจะไม่เปลี่ยนช่วงเดิม
- ลูกศรซ้าย/ขวาเลื่อนช่วงก่อนหน้า/ถัดไปเท่าจำนวนวันเดิม รวมวันเริ่มต้นและสิ้นสุด โหมดเดือนเลื่อนเป็นเดือนปฏิทิน รองรับเดือนสั้น/ยาว ปีอธิกสุรทิน และข้ามปี
- Sales (Daily) พร้อม Sale by Category / Discount, กราฟรายวัน/แยกเดือน, Entertain · Period และ Report Detail กรองตามช่วงวันที่เลือก; Sale (Monthly) แยกเป็นยอดสะสมทุกวันที่มีรายงานในเดือนของวันสิ้นสุด ส่วน Guest · Daily และ Entertain · Daily ยังใช้วันสิ้นสุด
- แสดงจำนวนวันที่มีข้อมูลเทียบกับจำนวนวันที่เลือก วันที่ไม่มีรายงานคงวันที่นั้นไว้และแสดง NO DATA ไม่ถูกแทนด้วยศูนย์หรือยอดวันอื่น กด “วันที่มีข้อมูลล่าสุด” แล้วกด “เลือก” เพื่อกลับมาวันที่มีข้อมูลได้เอง โดยไม่กระโดดกลับอัตโนมัติ
- ตัวอย่างชุดต้นแบบ: เลือก KAPPO 02/09/26–30/09/26 จะยังเห็น Sale (Monthly) 32,100 บาทของเดือนกันยายนจากรายงาน 01/09/26 แต่ Sales (Daily) ของช่วง 02/09/26–30/09/26 และกราฟเป็น NO DATA; หากเลือก 01/09/26–02/09/26 Sales (Daily) จะรวมรายงานวันที่ 01/09/26 เป็น 32,100 บาท แม้วันที่ 02/09/26 ไม่มีรายงาน
- Refresh โหลดหน้าและข้อมูล snapshot ที่แนบกับ HTML ใหม่จริง โดยจำร้าน, Period, โหมดช่วง และแท็บรายงานผ่าน URL fragment (หลัง #) ใช้ได้แม้ปิด browser storage และไม่ใส่ข้อมูลรายงานใน URL
- แสดงเวลาโหลดหน้า (เวลาไทย) ไม่ใช่เวลาซิงค์ POS; ไม่มีการอ่านไฟล์ POS ใหม่หรือเชื่อมฐานข้อมูลเพิ่ม การแก้ข้อมูลใน Source ต้องสร้าง HTML ใหม่ก่อน
- ถ้ามีไฟล์ในคิว Import ปุ่ม Refresh จะขอคำยืนยันก่อนล้างคิว กดยกเลิกแล้วคิวและหน้าปัจจุบันยังคงเดิม การเปลี่ยน Period/ร้านไม่ล้างคิว
- ปฏิทินรองรับ ค.ศ. 1900–2100; ไม่ยอมใช้ช่วงวันที่ไม่ครบ วันเริ่มหลังวันสิ้นสุด หรือวันที่ไม่ถูกต้อง
- วันที่บนหน้าจอและช่อง Import Business Date ใช้ DD/MM/YY เช่น 03/09/26; ประวัติ Master แสดง DD/MM/YY พร้อมเวลาไทย รายเดือนแสดง MM/YY เพราะเป็นยอดทั้งเดือน ไม่สร้างวันที่ขึ้นเอง
- หัวปฏิทินใช้ชื่อเดือนภาษาไทยและปี ค.ศ. เต็มตาม Reference ช่องกรอกปี 2 หลักอิงศตวรรษของวันที่ที่เลือก (ค่าเริ่มต้น 2000–2099); หากเปลี่ยนศตวรรษให้เลือกปีในปฏิทิน หรือพิมพ์ปี 4 หลัก แล้วออกจากช่องเพื่อย่อเป็น DD/MM/YY
- วันที่ภายในระบบ, URL และ Backup ยังคง ISO เพื่อไม่ให้เกิดความกำกวม; ชื่อไฟล์และรายงานต้นฉบับไม่เปลี่ยน ก่อน Refresh ให้บันทึก Backup ของข้อมูลที่นำเข้าและ Master ที่แก้ไขไว้

## Sale (Monthly) และ User Guide

- Sale (Monthly) รวมรายงานของร้านเดียวกันตั้งแต่วันแรกถึงวันสุดท้ายของเดือน โดยยึดเดือนของวันสิ้นสุดที่เลือก เช่น เลือกช่วงข้าม 2 เดือน จะรวมเฉพาะเดือนของวันสิ้นสุด ไม่รวมยอดทั้งสองเดือนเข้าการ์ดเดียว
- Import วันใหม่ในเดือนนั้นสำเร็จแล้ว ยอดขายสะสม, Sale by Category และ Discount ของ Monthly อัปเดตพร้อมกัน รายงานที่มีอยู่ในเดือนเดียวกันนับทั้งหมด แม้วันที่รายงานจะอยู่นอกช่วงที่เลือก
- Import วันเดิมแทนชุดเดิม ไม่บวกซ้ำ หากรายงานแก้ไขมียอดน้อยลง Monthly จะลดตามข้อมูลจริง ไม่บังคับเพิ่มเสมอ วันของเดือนอื่นไม่ถูกรวมและข้อมูลแต่ละร้านแยกกัน

## Import และการแยกร้าน

1. กด Import File (ใช้ได้ทั้ง Dashboard และ Master Data) → เลือกร้าน / รหัสสาขา / วันที่ธุรกิจ
2. เลือก A103/S102/S104/S114/S117 อย่างละ 1 ไฟล์ รวม 5 ไฟล์ของวันเดียวกัน
3. กด Verify Reports → ตรวจจำนวนแถว ยอด และข้อควรตรวจ
4. กด “Save Backup” แล้วตรวจว่า Revenue-Backup…json อยู่ในเครื่อง
5. ติ๊กยืนยันปลายทาง/ข้อควรตรวจ/ไฟล์สำรอง → กด “Confirm Import”

หัวข้อส่วนนี้ใช้ “Import File” ชื่อปุ่ม/ช่องเลือก/หัวตารางเป็นภาษาอังกฤษ และคำอธิบาย คำเตือนกับข้อความยืนยันยังเป็นภาษาไทย

- A103/S114/S117 ใช้ PDF ที่เลือกคัดลอกข้อความได้; S102/S104 ใช้ UTF-8 CSV หรือ Excel .xlsx / .xls แบบ BIFF ตามหัวคอลัมน์ Easy Restaurant ไม่รองรับ PDF สแกน / ไฟล์ Category แทนรายงานขาย / ไฟล์ HTML หรือ CSV ที่เพียงเปลี่ยนนามสกุลเป็น .xls
- Business Date เลือกจากปฏิทินได้ทุกวันที่รองรับ แม้ยังไม่มีข้อมูล เป็นวันที่ธุรกิจ 1 วันต่อชุด Import ไม่ใช่การนำเข้าช่วงหลายวัน กด Apply เพื่อใช้หรือ Cancel เพื่อคงวันเดิม จากนั้น Choose File แล้ว Verify Reports
- Verify แสดงสาเหตุเมื่อเลือก Report อื่น เช่น S105/S107 หรือชื่อไม่ตรงเนื้อหา รวมถึงไฟล์ซ้ำ/ไม่ครบ และปิดทาง Confirm Import จนผ่านครบทั้ง 5 รายงาน; ข้อมูลเดิมไม่ถูกล้าง
- ชื่อไฟล์ไม่ใช้ตัดสินร้าน อ่านชื่อร้าน/วันที่/สาขาจาก PDF และ SaleDate จาก S104; ช่องที่ต้นฉบับไม่ระบุต้องยืนยันเอง
- ไฟล์ไม่ครบ ผิดโครงสร้าง ผิดวัน/ร้าน หรือยอดต่างเกิน 0.02 บาทจะไม่เปลี่ยน Dashboard ส่วนต่างเล็กน้อยจะแจ้งเตือนและคงยอดดิบ
- ชุดวันเดิมถูกแทนทั้งชุด ไม่บวกยอดซ้ำ; เพิ่มวันใหม่แล้ว Period/กราฟรวมได้หลายวัน และ Report Detail เลือกวันได้
- Capricci ใช้ S104 + ส่วนลด S114 ที่ตรวจตรงกันตาม ItemCode เพื่อคืน Gross sales → จัดหมวดผ่าน Master; ItemCode ใหม่เป็น “ยังไม่จัดหมวด” และแสดงยอดหมวดนี้แยก ไม่เดาว่าเป็น Other
- รายการเดิมใน Master ไม่ถูกทับการจัดหมวด; ถ้ากำลังแก้แบบร่าง ต้องกดทดลองใช้ก่อนนำเข้า
- รุ่นนี้รองรับ 1 สาขาต่อร้านต่อชุดข้อมูล และนำเข้าชุดรายวันครบทั้ง 5 Report ไม่ใช่การนำเข้าทีละ Report
- หลัง Refresh/ปิดหน้า กด “Open Backup” → ตรวจและกด “Restore Backup” เพื่อกลับมาใช้ข้อมูล Import และ Master ที่สำรองไว้ เก็บ HTML นี้คู่กับ Backup
- “Export Current Data” บันทึกชุด Import ทั้งหมด + Master ที่ใช้อยู่; ควรสำรองใหม่หลังจัดหมวด ไม่มีการบันทึกอัตโนมัติหรืออัปโหลด Google Drive
- Backup มีต้นฉบับรายงานและ SHA-256; เปิดกลับแล้วตรวจเนื้อหาใหม่ ไม่เชื่อข้อมูลยอดที่แก้ไว้ใน JSON โดยตรง ไฟล์มีข้อมูลธุรกิจ/เลขภาษี ควรเก็บอย่างจำกัดสิทธิ์

รายละเอียดรุ่นใช้งานในเครื่อง: `source/docs/local-sales-import.md` · แผนส่วนกลางหลัง Final: `source/docs/import-routing.md`

## ตัวกรอง ItemCode ของ Capricci

หน้า Master Data มี Dropdown Type = Main. (P), Sub Type = Sub. (O) และ Category = Category (D) จากชีต Category ใช้ร่วมกับช่องค้นหาและตัวกรองรายการขาย/หมวดขัดกันได้ กด “ล้างตัวกรอง” เพื่อกลับมาดูทั้งหมด การกรองมีผลเฉพาะตาราง ไม่เปลี่ยนยอด Dashboard

Sub Type แสดงเฉพาะรายการใน Type ที่เลือก หากเปลี่ยน Type แล้ว Sub Type เดิมไม่อยู่ในกลุ่มใหม่ ระบบจะกลับเป็น “ทั้งหมด” โดยอัตโนมัติ; หากยังอยู่ในกลุ่มจะคงตัวเลือกเดิม เมื่อ Type เป็น “ทั้งหมด” จะเลือกได้ทุก Sub Type

Category แสดงเฉพาะหมวดใน Type และ Sub Type ที่เลือก หากเปลี่ยนตัวเลือกด้านบนแล้ว Category เดิมไม่ตรงกัน จะกลับเป็น “ทั้งหมด” เมื่อ Sub Type เป็น “ทั้งหมด” จะแสดงทุก Category ภายใน Type ที่เลือก และเมื่อทั้งคู่เป็น “ทั้งหมด” จะแสดงทุก Category

ตารางเรียง Type → Sub Type → Category → Menu → Output → ปุ่มแก้ไข โดย ItemCode อยู่ใต้ Menu และ Type “Wine” แยกจาก Output “Beverage - Alcohol”

Category อ่านตามเซลล์รวมใน Excel; 240 รหัสมี Category และ 535 รหัสไม่มีค่าจึงแสดง “ไม่ระบุ” ไม่เดาหมวดจากชื่อหรือรหัสสินค้า รายการที่เพิ่มใหม่และยังไม่มี Category ต้นฉบับจะแสดง “ไม่ระบุ” เช่นกัน

## ข้อจำกัดและความเป็นส่วนตัว

เป็น UX/UI และ source snapshot ไม่ใช่ระบบ Finance production ไม่มีฐานข้อมูล, API, Login หรือการควบคุมสิทธิ์จริง ปุ่มนำทางบางส่วน, Notifications และ Logout ยังเป็น placeholder ส่วน Refresh และ Period ทำงานกับข้อมูลในหน้าแล้ว

การนำเข้าและ Backup ทำงานในเครื่องแล้ว แต่ยังไม่ใช่ระบบหลายผู้ใช้ ส่วนประกอบ server/framework เดิมมีรายการเตือนความปลอดภัยที่ต้องอัปเดตและทดสอบก่อน Deploy จริง ดูรายละเอียดใน `source/docs/local-sales-import.md` ไม่มีการ Deploy หรือเชื่อมบัญชีในรอบนี้

HTML เป็นผลส่งออกจาก React หากแก้ Source ภายหลังต้องสร้าง HTML ใหม่

ชุดส่งมอบมีตัวเลขธุรกิจ ชื่อลูกค้านิติบุคคลและเลขผู้เสียภาษีจาก A103 ควรส่งต่อเฉพาะผู้มีสิทธิ์ ไม่ได้อัปโหลดหรือเผยแพร่ภายนอก และไม่ลบ/แก้ไขรายงาน PDF/CSV ต้นฉบับ

ห้ามนำ HTML ตัวอย่างนี้ขึ้นเว็บไซต์สาธารณะโดยตรง เพราะฝังข้อมูลธุรกิจจริง รุ่น Final ต้องแยกข้อมูลออกและอ่าน Google Drive ผ่าน API ที่ตรวจสิทธิ์ผู้ใช้ GitHub Pages ถ้าเลือกใช้จะเป็นส่วนหน้าเว็บ ไม่ใช่ฐานข้อมูลหรือ API กลาง

ZIP ไม่รวม node_modules, build cache, .git, token, .env หรือไฟล์รายงานต้นฉบับ แต่มีข้อมูลที่สกัดไว้สำหรับแสดงผล การตั้งค่า Sites ในสำเนาไม่ผูก project_id เดิม
